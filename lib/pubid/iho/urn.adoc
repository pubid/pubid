= IHO URN schemes

This file is the single home of the IHO flavor's URN documentation (the
per-flavor split of the former `docs/URN-SCHEMES.adoc`, owner ruling
2026-11-25: "for URN schemes how can we mix up different flavors in 1
file? SPLIT THE FILE!"). It covers the three schemes the flavor carries:

1. the official URN (`#to_urn`) — the adopted IHO MRN guidance form for
   the S/P/M series, the legacy positional form for the B/C series;
2. the legacy positional `urn:iho:` grammar — decodable for every
   series, emitted only by the B/C series;
3. the pubid-scheme URN (`#to_pubid_urn`) — pubid's own
   `urn:pubid:iho:` codec, not governed by the IHO guidance.

The implementations are `lib/pubid/iho/urn_generator.rb` and
`lib/pubid/iho/urn_parser.rb`; the flavor's component law lives in
`lib/pubid/iho/CLAUDE.md`.

== The adopted IHO MRN guidance (owner ruling, 2026-11-25)

Source: S-100WG4, "MRN Guidelines for IHO" (the IHO Level guidance for
publications, pages 8-9). The guidance proposes the Publications MRN

    urn:mrn:iho:pub:<publication type>:<publication name or number>:<edition number>[:<correction number>[:<clarification number>[:<optional and additional version information>]]]

with the publication types `bathy` | `cb` | `reg` | `per` | `spec`, and
the example `urn:mrn:iho:pub:spec:s57:3:1:supplement3` (S-57 Ed 3,
Corr. 1, Supplement 3). IHO's own printed S-98 metadata carries
`urn:mrn:iho:pub:spec:s98:1.0.0` — the DOTTED edition in the canonical
4th position, which this flavor adopts verbatim.

pubid adopts the guidance as the flavor's official-URN emission for the
series the guidance types:

[cols="3,1,4,4",options="header"]
|===
| series | type | law | example
| S (Standards and Specifications) | `spec` | the guidance's own code | `IHO S-44 5.0.0` → `urn:mrn:iho:pub:spec:s44:5.0.0`
| P (Publication, the periodic series) | `per` | the guidance's Periodic Publications code | `IHO P-5 Vol. 2024` → `urn:mrn:iho:pub:per:p5:vol-2024`
| M (Miscellaneous Base Regulatory Publications) | `reg` | the guidance's own code | `IHO M-2 Sup 1` → `urn:mrn:iho:pub:reg:m2:sup-1`
| B (Bibliographic) | — | no guidance code: the legacy emission below, until IHO assigns one | `IHO B-4 2.19.0` → `urn:iho:b:4:ed-2.19.0`
| C (Circular Letter) | — | no guidance code: the legacy emission below, until IHO assigns one | `IHO C-13 1.0.0` → `urn:iho:c:13:ed-1.0.0`
|===

=== The name form

`<name>` is the lowercase series letter + number — the guidance's own
`s57`/`s98` spelling:

    IHO S-100  ->  urn:mrn:iho:pub:spec:s100

=== The S-158 member encoding (issue #774)

S-158 is a framework publication defining a series of separate check
specifications (`S-158:100` generic, `S-158:1xx` product-specific,
`S-158:98` interoperability, `S-158:128` catalogue; the `product`
component carries the member number). The member joins the name segment
hyphenated — the documented fleet extension of the guidance for
compound publication numbers — so the edition stays in its canonical
4th position exactly like the S-98 metadata:

    S-158 1.0.0      ->  urn:mrn:iho:pub:spec:s158:1.0.0
    S-158:102 1.0.0  ->  urn:mrn:iho:pub:spec:s158-102:1.0.0

The member designator is order-stable: every citation spelling
(`S-158 0.2.0 Part S-102`, `S-158 Part S-102 0.2.0`, `S-158-S-102`,
the draft-era aliases of issue #775) emits the identical URN.

=== The edition segment

The dotted `x.y.z` edition emits BARE (not `ed-`-prefixed), in the
canonical 4th segment — the S-98 precedent. An edition-non-specific
reference emits no edition segment. A component's own edition (the
separately-published mode) rides as `ed-` right after its component,
keeping the two modes decodable:

    IHO P-6 Vol. 2 1.0.1       ->  urn:mrn:iho:pub:per:p6:vol-2:ed-1.0.1
    IHO S-98 Part A 1.0.0 (2024) ->  urn:mrn:iho:pub:spec:s98:part-A:ed-1.0.0:year-2024

=== The trailing atoms

The components the guidance's tail slots do not model emit as
lowercase marker segments, RFC 3986-safe, in the containment order.
Values are case-preserved (identity law: `part-A` and `part-a` are
distinct documents; `appendix-D-2` keeps its letter). The Appendix
subnumber hyphen-joins its appendix as one compound segment; the base
with-year qualifier keeps its `year-` marker; the S-4 spec citation is
a child of its part (`spec-`, `specsub-`, `specvar-`; the SECTION is
derivable, never emitted):

    [:year-<yyyy>][:sup-<n>[:ed-…][:year-…]]
    [:part-<X>[:ed-…][:year-…]]
    [:spec-<n>[:specsub-<n>][:specvar-<X>]]
    [:annex-<A>[…]]
    [:appendix-<B>[-<sub>][…]]
    [:vol-<n>[:issue-<n>][…]]

Examples:

    IHO S-100 5.0.0 Part 2 (2024) -> urn:mrn:iho:pub:spec:s100:5.0.0:year-2024:part-2
    IHO S-122 1.0.0 Appendix D-2  -> urn:mrn:iho:pub:spec:s122:1.0.0:appendix-D-2
    IHO S-4 4.10.0 B-401          -> urn:mrn:iho:pub:spec:s4:4.10.0:part-B:spec-401
    IHO P-1 Vol. 30 (2)           -> urn:mrn:iho:pub:per:p1:vol-30:issue-2

The guidance's bare correction/clarification slots (the `s57:3:1`
form) are NOT modeled faces — the flavor has no correction component —
and a bare digit tail segment rejects on decode.

== The legacy positional grammar (decode-only for S/P/M; the B/C emission)

The pre-guidance emission — `urn:iho:<type>:<number>[:ed-<x.y.z>]
[:sup-…][:part-…][:annex-…][:appendix-…][:<sub>][:vol-…][:issue-…]
[:year-…]` — stays fully decodable for every series and remains the
emission of the B/C series (no guidance type code). Its laws:

- the docnumber occupies the first bare number segment; a further bare
  digit segment binds the S-158 member (`urn:iho:s:158:100`), never
  glued into the number (issue #774);
- `ed-` and `year-` are POSITIONAL: the edition attaches to the node it
  follows (the base when no component precedes it, else that
  component's own edition); a year belongs to a component only when it
  follows that component's own edition;
- containment: part ⊃ annex ⊃ appendix ⊃ subnumber (the bare digit
  atom, only directly after its appendix); vol ⊃ issue;
- the number may span bare segments only through the member slot; a
  colon number and a volume stay distinct because the volume is
  marker-tagged (`urn:iho:s:158:2024` vs `urn:iho:s:158:vol-2024` —
  the #637 hazard, kept under the positional scheme);
- the legacy 2.0.x spellings (the dotted keys `part.4a`/`suppl.1`/
  `ap.A`/`vol.30`/`issue.2`/`appendix.D-2`, the bare `a.b.c` edition
  segment, the `y.2024` yearbook tag) decode but are never emitted.

Both decode paths build through `Builder.build` — the S-158 alias
unification (a draft-era `part-S-102` URN resolves to the
`product` identity) and every other semantic validation is shared
with the text parse.

== The pubid-scheme URN (`urn:pubid:iho:`)

pubid's own lossless codec (issue #670;
`lib/pubid/iho/pubid_urn_schema.rb`). NOT governed by the IHO guidance
— the atoms carry the full typed model and always round-trip
(`Pubid.parse_urn(id.to_pubid_urn).to_hash == id.to_hash`).

    urn:pubid:iho:std:100:ed-5.0.0:year-2024:part-2   IHO S-100 5.0.0 Part 2 (2024)
    urn:pubid:iho:std:158:product-102:ed-1.0.0         IHO S-158:102 1.0.0
    urn:pubid:iho:std:122:ed-1.0.0:appendix-D:appsub-2 IHO S-122 1.0.0 Appendix D-2
    urn:pubid:iho:pub:5:vol-2024                      IHO P-5 Vol. 2024

Types: `std` (S), `pub` (P), `m` (M), `b` (B), `cl` (C), `id`.
Atoms, canonical order: `product-` (the S-158 member, riding the
document code before the edition — issue #774), `ed-`, `year-`,
`sup-`/`suped-`/`supyear-`, `part-`/`parted-`/`party-`, `spec-`/
`specsub-`/`specvar-`, `annex-`/`anned-`/`annyear-`, `appendix-`/
`appsub-`/`apped-`/`appyear-`, `vol-`/`issue-`/`voled-`/`voly-`. Case
is preserved (`part-A`); the yearbook year is a volume (`vol-2024`, no
`year-` value). The S-158 member emits the typed `product-<NNN>` atom —
the draft-era part-faceted emission (`part-S-102`, `parted-`) is dead:
the `from_hash` unification redirects the legacy form onto the
`product` identity, so the legacy URN fails the canonical gate.
