[[urn-ansi]]
= ANSI URN schemes

This file is the single home of the ANSI (`ansi`) flavor's URN
documentation — the per-flavor split of the former `docs/URN-SCHEMES.adoc`
(owner ruling 2026-11-25: "for URN schemes how can we mix up different
flavors in 1 file? SPLIT THE FILE!"). The index that links every flavor's
file is `docs/URN-SCHEMES.adoc`.

Namespace: `urn:pubid:ansi:`. Schema: `lib/pubid/ansi/pubid_urn_schema.rb`.
Landed with the IEEE wave, which nests ANSI ids.

Official URN: none. ANSI has no namespace in the IANA registry, and the
current `urn:ansi:…` form of `to_urn` is pubid-invented. Current `to_urn`: 192
ids; 136 re-parse to an equal identifier (`urn:ansi:X9.62:2005`), the rest
carry a co-publisher or a part that `UrnParser` does not read.

pubid scheme: all 192 pass ids emit, round-trip by `to_hash`, are path-safe,
and give no collision. A trailing `-YYYY` is the year (relaton#45), so
`ANSI 802.3-2012` is `urn:pubid:ansi:std:802.3:pub-ANSI:year-2012:f:0.datesep--`:
the dash is the spelling facet `datesep`, and cutting the `f` group gives the
URN of `ANSI 802.3:2012`, the same document.

[cols="3,1",options="header"]
|===
| `_type` | token
| `pubid:ansi:standard` | `std`
| `pubid:ansi:american-national-standard` | `ans`
| `pubid:ansi:identifier` | `id`
|===

Core: `number`. Atoms: `pub-` (`publisher.body`), `co-`
(`copublishers.*.body`), `type-` (`type.abbr`), `part-`, `subpart-`,
`year-`, `dateyear-`/`datemonth-`/`dateday-`/`undated-`, `ed-`
(`edition.number`), `stage-` (`stage.abbr`), `iter-`, `lang-`, `loc-`.
Facets: `langsrc`, `edsrc`. A component maps through its identifying field
only; its registry fields (`name`, `harmonized_stages`) are not placed, so a
value there raises rather than enter the URN.

----
ANSI 802.3-2012                urn:pubid:ansi:std:802.3:pub-ANSI:part-2012
----

Finding: ANSI stores the year of `ANSI 802.3-2012` in `part` (`2012`), and
the URN keeps it as it is (`part-2012`).
