[[urn-bsi]]
= BSI URN schemes

This file is the single home of the BSI (`bsi`) flavor's URN
documentation — the per-flavor split of the former `docs/URN-SCHEMES.adoc`
(owner ruling 2026-11-25: "for URN schemes how can we mix up different
flavors in 1 file? SPLIT THE FILE!"). The index that links every flavor's
file is `docs/URN-SCHEMES.adoc`.

Namespace: `urn:pubid:bsi:` (the `_type` flavor segment).

Official URN: none. The organization has no namespace in the IANA registry, and the current `urn:bsi:…` form of `to_urn` is pubid-invented (legacy, no round-trip promise).

Current `to_urn` (≤400 sampled pass ids): 400 ids, 34 round-trip, 84 reshape, 282 do not re-parse, 0 raise, 0 empty, 6 colliding URNs.

*Landed (issue #670) with all 34 types.* The draft's atom list is the
landed one, with three kind corrections the corpus forced:
`typed_stage.abbr` is a list (the stage's abbreviation array), the Flex
month is an Integer and `reverse_format` is a bool. An adopted norm
carries the European document along `base`, so the wrapper shares the slug
prefix of the document it wraps (`BS EN 1073-2:2002` is
`urn:pubid:bsi:cencenelec.en:1073:part-2:year-2002:aen`) — the qualified
`cencenelec.` token keeps the document's own schema. All 1,495 corpus rows
emit (5 fail `parse`, the fixture spec's concern).

Finding (resolved by the NIST ruling, no `to_hash` change): `type`,
`stage` and `typed_stage` serialize every registry field of their
components, so each field is its own atom (`typeabbr-`, `stagehs-`,
`tsabbr-` …). Reducing them to one identifying value would change
`to_hash` and need a re-crawl — a separate decision.
