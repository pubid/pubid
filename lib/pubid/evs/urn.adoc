[[urn-evs]]
= EVS URN schemes

This file is the single home of the EVS (`evs`) flavor's URN
documentation — the per-flavor split of the former `docs/URN-SCHEMES.adoc`
(owner ruling 2026-11-25: "for URN schemes how can we mix up different
flavors in 1 file? SPLIT THE FILE!"). The index that links every flavor's
file is `docs/URN-SCHEMES.adoc`.

Namespace: `urn:pubid:evs:` (the `_type` flavor segment).

Official URN: none. The organization has no namespace in the IANA registry, and the current `urn:evs:…` form of `to_urn` is pubid-invented (legacy, no round-trip promise).

Current `to_urn` (≤400 sampled pass ids): 36 ids, 29 round-trip, 7 reshape, 0 do not re-parse, 0 raise, 0 empty, 4 colliding URNs.

Corpus: 36 of 36 pass ids parse.

Atoms, canonical order: `part-` (`part`), `year-` (`year`), `lang-` (`language`), `amdkind-` (`amd_kind`), `amdnumber-` (`amd_number`), `amdyear-` (`amd_year`), `corkind-` (`cor_kind`), `coryear-` (`cor_year`), `evstype-` (`evs_type`), `intlorg-` (`intl_org`), `nayear-` (`na_year`).

*Landed (issue #670) as drafted*, with two kind corrections: `draft_prefix`
is the bool the corpus serializes, and an adoption of a European document
carries it along `base`, so it keeps the CEN/CENELEC schema with a
qualified token (`EVS-EN 18216:2026` is
`urn:pubid:evs:cencenelec.en:18216:year-2026:na`); `intlorg-` covers an
adoption of an organization pubid does not model as a nested identifier.
All 36 corpus rows emit.

Facet candidates (spelling-only): `separator`, `amd_separator`, `cor_separator`, `na_separator`.

`draft_prefix` was a facet when the schema landed and is an atom now
(`draftprefix-`, bool, after `nayear-`): `prEVS-EN 100:2026` is the draft,
another document than `EVS-EN 100:2026`, so identity compares it (issue
#656), as CEN/CENELEC's strict stage does for `prEN`.

Nested identifiers of other flavors (written with their own schema, qualified token `<flavor>.<token>`): `cencenelec`, `iec`, `iso`.
