# Cross-flavor `number`/`part`/`subpart` retype history

Moved out of the root `CLAUDE.md` (which is capped at 100KB, see
`spec/pubid/flavor_notes_spec.rb`) to keep that file loadable in every
session. `CLAUDE.md` keeps a one-line pointer here; this is the full
narrative behind it.

- **`number`/`part`/`subpart` are `:string` on `::Pubid::Identifier` — the retype is COMPLETE**: `lib/pubid/identifier.rb` declares all three as plain strings, so **no flavor redeclares them and the determinism landmine is gone**. `root.number` is a `String` for every flavor (the one exception is `plateau`, which declares `:integer` on purpose). The tripwire specs that policed the mixed state are **inverted, not deleted** — the nine per-flavor `root_number_spec.rb` blocks, `spec/pubid/omg/part_string_spec.rb` and the first block of `spec/pubid/number_string_retype_spec.rb` now assert the String, so a flavor that reintroduces a boxed `number` still turns red. **`Pubid::Components::Code` itself stays**, and that distinction is the rule to carry forward: a component earns its place when it has more than one significant field or real behaviour, and the class still types about 18 flavor-owned attributes that nothing inherits (NIST `series`/`subseries`/`first_number`/`second_number`/`parts`, ITU `code`, CSA `cec_part`/`no_number`, BSI `second_number`/`spec_code`). **The last four flavors converted in this order, each with a baseline replay**: sae+ccsds (SAE flattens `{"value" => X}` → `X`; there is no relaton-data-sae), **iso** (its Code was unreachable — `parts` never written, never read — and the branch also took the committee codes, `subgroup` and `edition.number`; see `lib/pubid/iso/CLAUDE.md`, and note `relaton-data-iso` needs a re-crawl for 5 `subgroup` rows), **nist** (`Code#part` was a `value.split("-")` reader no library code called; `CrplReport#number` normalised into a *new* Code and now returns the string; `to_hash` unchanged because the compact layer already flattened), and the base flip, which converted **csa** for free because it redeclared nothing. **Measured across the four branches: 30,285 identifiers replayed, and `to_s`/`to_urn`/`to_mr_string`/`root.number`/class are byte-identical for every one**; only 12 ISO hashes move. The historical sequencing note follows. **Tranche 1 of 3 (ansi, api, bsi, cen_cenelec, idf, jcgm), plus IEC**: `::Pubid::Identifier` declares all three as `Components::Code` (`lib/pubid/identifier.rb:136-138`). Every index-key branch of the last month had to tiptoe around the resulting landmine — **a `number` redeclaration on a class that others INHERIT FROM resolves nondeterministically under multi-flavor load** — and twelve flavors now carry a structural tripwire spec whose only job is to police it. That hazard exists *only* because the parent declares a component while the leaves redeclare a scalar; make both sides agree and the whole bug class disappears. The conversion is deliberately **sequenced in three tranches, not one branch**: this is tranche 1, the six flavors that stored a String in a box. **The base declaration at `identifier.rb:136-138` is NOT touched here** — it moves last, after ISO/NIST (tranche 3) and CSA (tranche 2) convert; `spec/pubid/number_string_retype_spec.rb`'s first block asserts it is still `Components::Code`, so a later branch cannot jump ahead silently. **IEC converted next, out of the original tranche order** — it was never in the hand-off's table because it declares its own `Iec::Components::Code`, but that subclass turned out to be dead (it rendered a `prefix` no construction path ever set) and the Code/String split between `parse` and `new` was making a hand-built IEC identifier silently not `==` the parsed one. The flavor detail, the `key_value` placement that replaced the wrapper denylist, and the three converter groups that went with it are in `lib/pubid/iec/CLAUDE.md`. **(Historical: at that point iso, nist, csa, sae and ccsds still declared a `Components::Code`; all five have since converted.)**
  **The measurement that justifies the scope** (whole fixture corpus, no sample cap — the hand-off's own table was capped at 500 lines/flavor and undercounted): across all 2,066 pass-fixture identifiers of the six flavors, **not one** populates `prefix`, `part`, `subpart` or `parts` inside the Code, and `number.parts` / `number.prefix` have **zero** call sites anywhere in `lib/`. Two findings recorded for the later tranches: **NIST is far less structured than the hand-off feared** — 7,041 of 21,349 NIST ids look structured, but the only field populated is `Code#part`, a *computed reader* (`nist/components/code.rb:18-23`) that splits `value` on `-`; `prefix`/`subpart`/`parts` are populated **zero** times. **ISO and IEC also show 0 structured root numbers** (7,565 / 9,946 ids) despite both overriding `to_s` to compose `parts`/`prefix`.
  **Placement rule (the one that matters).** lutaml deep-dups the parent attribute table into each subclass **at class-definition time**, so a base-level declaration is safe iff the base's class body lives in **one file and is never reopened** — Ruby resolves the superclass constant to completion before opening a subclass body (the W3C precedent; IEEE's split base is the counter-shape). All six satisfy it, so each declares the three attributes **once, on its own `Identifier`**, not on leaves: ansi/api/idf/jcgm in their `identifier.rb`; **BSI in `single_identifier.rb`**, which is the sole home of the `Pubid::Bsi::Identifier` body (`bsi/identifier.rb` is a comment-only load stub, and `bsi/model.rb` defines a *conflicting* `Bsi::Identifier < Lutaml::Model::Serializable` that `bsi.rb` deliberately never autoloads); **CEN/CENELEC in `identifier.rb`**, the shared parent of *both* its branches — one declaration there replaced **three that disagreed** (`Identifiers::Base` said `:string`, `SingleIdentifier` inherited `Code`, `SupplementIdentifier` declared `Code` again).
  **Delete a same-type redeclaration, do not leave it.** Six were removed (BSI's three leaves + `Handbook#part`, CEN's `Identifiers::Base#number`, API's `SingleIdentifier#part`, JCGM's `SingleIdentifier#number`). They are no-ops for *type* resolution once the base agrees, but **a redeclaration moves the generated accessor's `owner` onto that class**, which is observable: `spec/pubid/number_string_retype_spec.rb` discriminates a hand-written delegation from a lutaml accessor by comparing `instance_method(attr).owner` to the flavor's `Identifier`, and the leftover CEN declaration made every `Amendment`/`Corrigendum`/`Fragment`/`ConsolidatedIdentifier` look "delegated", silently skipping them in the corpus type check. A code review caught it; the `perl` deletion had missed the file because its class nests one level deeper (8-space indent, not 6).
  **The wire format flattens, by design.** `{"value" => "9001"}` → `"9001"` for **ansi, api, bsi, cen_cenelec, idf** (none declares a `key_value` block). **JCGM is unaffected** — it already flattened explicitly through `number_to_kv`, whose converter now reads the scalar directly. **No index migration follows, and that was checked rather than assumed**: of the six, only JCGM has a `relaton-data-*` repo at all — there is no `relaton-data-bsi`, `-ansi`, `-api`, `-cen*` or `-idf` — and JCGM is exactly the one whose wire format does not move. All **27** rows of the published `relaton-data-jcgm/index-v1.yaml` deserialize and re-serialize **byte-identically** under this change (they already store a bare `number: '100'`). So the flattening is real but reaches nothing published; a *future* BSI or CEN index must simply be crawled after this lands, not migrated.
  **Two shims keep the mixed-type period working, and they are not temporary scaffolding to delete lightly** — ISO/IEC/NIST/CSA/SAE/CCSDS still hold a `Components::Code`, and a *wrapper* routinely delegates to a nested identifier of another flavor. `Renderers::Base#render_component` (inherited by `HumanReadable` and `DirectivesRenderer`) and `Bsi::Renderer#component_str` read through `respond_to?(:render) ? render(context:) : to_s`; `Rendering::Numbering#numbering_value` does the same for `.value`. `UrnGenerator::Base#urn_number`/`#urn_part`/`#urn_subpart` already branched on `is_a?(Components::Code)`, which is why ANSI's and API's URNs needed no change at all. The shared `BundledIdentifier#to_urn` was reading `supplement.number.value` unguarded on a `polymorphic: true` attribute — inert today but a `NoMethodError` waiting for the first converted flavor to be nested there; it now reads through either shape.
  **`Pubid::Identifier.own_base_class` — a real defect the retype exposed.** A flavor's own `Identifier` base was **absent from its `polymorphic_type_map`**, because the map is built from `scanned + registered + additional` and the base lives outside `Identifiers::`. BSI's builder instantiates that base directly for the members of a bundled identifier, so those members serialize with `_type: "pubid:bsi:identifier"` — which resolved to **nothing**, and a nested attribute typed `::Pubid::Identifier` then deserialized them as the **abstract root**. On `main` the round-trip *passed* anyway, because a nested `{"value" => "558"}` is exactly what the root's `Components::Code` expects; with a scalar number it started raising instead. The fix registers the base itself, appended **last** so `map[poly] ||= klass` still lets a concrete leaf win, and guarded against `self == ::Pubid::Identifier` (whose derived name would be the meaningless `"pubid:identifier:identifier"`). It is strictly a repair: **19 more BSI ids now round-trip and 28 more are `==` after `from_hash`**, with no id losing either.
  **Verification — replay a captured `main` baseline, do not trust the suite alone.** For the **retype itself** `to_s`, `to_urn`, `to_mr_string`, the identifier class and `root.number` are **byte-identical for all 2,066 ids** — that is the invariant a representation change must meet, and any diff would be a regression. The one deliberate exception is the API renderer repair described in `lib/pubid/api/CLAUDE.md`, which was measured separately and only ever *adds* the dropped number and type token; `to_hash` differs *only* by the `{"value" => X}` → `X` flattening, asserted mechanically by a recursive comparator rather than eyeballed, plus 74 BSI ids that previously **raised** `IncorrectModelError` and now serialize. Pre-existing round-trip failures (bsi 613, cen_cenelec 64, api 1 — none caused by the number type) are pinned as **exact counts** in `KNOWN_ROUND_TRIP_FAILURES`, the `PENDING_EQUALITY` convention, so both a regression and an accidental improvement turn the spec red.
  **Per-flavor detail**: the BSI cross-flavor set fix is in `lib/pubid/bsi/CLAUDE.md`; the dead fixture nets and the API renderer repair are in `lib/pubid/api/CLAUDE.md`.
