= URN schemes: the pubid scheme and the official URN
:toc:

Design for issue #656. Every flavor has two URN forms.

[cols="1,3,3",options="header"]
|===
| | pubid scheme | official URN

| Method | `Identifier#to_pubid_urn` | `Identifier#to_urn`
| Parse | `Pubid.parse_urn` (routes `urn:pubid:`), `Pubid.parse_pubid_urn` (accepts only this scheme) | `Pubid.parse_urn` (routes by namespace to the flavor `UrnParser`)
| Namespace | `urn:pubid:<flavor>:` | the namespace of the organization (`urn:iso:std:`, `urn:ietf:rfc:` …)
| Contract | always round-trips: `Pubid.parse_urn(id.to_pubid_urn).to_hash == id.to_hash`, corpus-wide; injective; path-safe | as faithful as the registered grammar allows; may be lossy
| Use | relaton slug for HTTP paths, API and parsing (relaton/relaton#441) | outward-facing render form; never a slug source
|===

The pubid scheme is implemented once, in `lib/pubid/pubid_urn/`, and reads
`#to_hash`. A flavor supplies only a schema (`lib/pubid/<flavor>/pubid_urn_schema.rb`)
that names its type tokens, its positional core and its atoms. `#to_urn` is
not changed by this design.

== The pubid-scheme grammar

----
pubid-urn = "urn:pubid:" flavor ":" body
body      = node *( ":" node ) [ ":f" 1*( ":" facet ) ]
node      = type-token *( ":" core ) *( ":" atom )
type-token= name / flavor "." name        ; qualified when the node is of another flavor
core      = value / "~"                   ; "~" = absent, only before a present core value
atom      = name "-" atom-value
atom-value= value / list / nested / nested *( "," nested )
list      = item *( "," item )            ; item = value / "~" (an empty item is "")
nested    = "(" flavor ":" body ")"
facet     = node-index "." name "-" ( value / list )
name      = %x61-7A *( %x61-7A / DIGIT )   ; a lower-case letter, then letters and digits
value     = *( ALPHA / DIGIT / "." / "_" / "-" / escape )
escape    = "~" 2HEXDIG-UPPER              ; one UTF-8 byte
----

Example: `ISO/IEC 13818-1:2015/Amd 3:2016` is
`urn:pubid:iso:is:13818:co-IEC:part-1:year-2015:amd:3:co-IEC:year-2016`.

=== Rules

Flavor:: The flavor segment of `_type` (`iso`, `cencenelec`, `3gpp`), so a
URN routes with `Pubid::TypeResolver` and needs no second table. The URN uses
the flavor of the identifier itself (the leaf); a node of another flavor
(for example the CEN layer of a BSI adoption) has a qualified token
(`cencenelec.aen`).

Nodes go root first:: A supplement (`amd`, `cor` …) is a node after the
node that it modifies, along `base`. So all supplements of a document share
the slug prefix of that document, and the chain is hierarchical.

Positional core:: A value that a type always has (normally the document
number) is a bare positional segment. The schema fixes the order of the core,
so the code layout cannot move it.

Prefixed atoms:: A value that can be absent is an atom `<prefix>-<value>`,
found by its prefix and not by its position. An absent atom leaves no
segment. The atoms of a type have one canonical order, declared in the
schema; the parser refuses an atom out of that order, a repeated atom and an
unknown atom.

No empty segment:: An absent value never leaves `::`. In a slug, `::`
becomes `//`, which servers and proxies collapse. An absent core value in the
middle of the core is `~`; absent core values at the end are dropped.

Escape:: Every byte outside `[A-Za-z0-9._-]` is `~XX` (upper-case hex).
`%` is not used, because servers decode `%2F` before they route, or refuse
it. So `:`, `,`, `(`, `)`, `/` and `~` never occur raw in a value.

Structure by shape:: A core value that has the *shape* of structure gets its
first character escaped: a lower-case letter first and then letters and
digits up to the end or up to a `-` (a type token, `f`, an atom), or
`<name>.<name>` with a letter in each part (a token of another flavor). So the
number `amd` is `~61md` and `iec.is` is `~69ec.is`, while `9001`, `802.11`,
`800-53` and `G.711` stay as they are. The rule reads the shape only, never
the schemas that exist, so a published URN keeps its meaning when a flavor,
a type token or an atom is added later. That is also why every type token,
atom prefix and facet name starts with a lower-case letter.

Canonical form:: Exactly one string for each identifier. The parser decodes,
rebuilds the identifier, encodes it again and refuses the input when the two
strings differ (a needless escape, an atom out of order, a trailing `~`).

Facets:: A value that records only a spelling (`original_code` "E" for
"en", `edition.original_text` "Ed 13") goes in the trailing `f` group, as
`<node-index>.<name>-<value>`. The full URN keeps facets, so the round trip
holds. A consumer can cut the `f` group off a slug, but then the slug no
longer round-trips (see <<open>>).

Nested identifiers:: A nested identifier that is not the `base` chain (an
adoption's `adopted`, an all-parts or consolidated `identifiers` list, a
bundle's `supplements`) is an atom whose value is a bracketed body,
`ids-(iso:is:9001)`.

Reserved tokens:: `f` (the facet group) and `type`
(`Pubid::IdentifierMetadata` already uses `urn:pubid:<flavor>:type:<key>` to
name a type, not a document; the parser refuses it).

Length:: An escape takes up to 9 characters for one CJK character, so the
1000-character limit of a printed identifier is too small for its URN. The
limit is `Pubid::PubidUrn::MAX_LENGTH` (16,000) on both sides: `#to_pubid_urn`
does not emit, and `Pubid.parse_urn` does not read, a longer URN. The
parser is linear-time, so the limit is a guard on size, not a ReDoS barrier.

Strict failures:: A malformed, unknown or non-canonical URN raises
`Pubid::Errors::UrnParseError`, also when its values decode but cannot be
cast into the identifier (the original error is the cause). `#to_pubid_urn` raises
`Pubid::Errors::InvalidInputError` when the flavor has no schema yet, and
when the schema does not place a value of `#to_hash` — a schema gap is loud,
never a silent drop.

=== The slug

The slug is the URN without `urn:pubid:`, with `:` replaced by `/`:
`iso/is/9001/year-2015/amd/1/year-2016`. The mapping is reversible, because
no value contains a raw `:` or `/`. A `/` inside brackets (a nested body) is
reversed in the same way.

=== Why per-flavor schemas and not a generic dump of `to_hash`

A generic `key-value` dump of `#to_hash` would round-trip with no schema, but
it is not positional, and it makes the URN depend on the attribute names of
the code. Issue #656 asks for a positional scheme derived from the ISO
grammar. The codec is shared; only the schema is per flavor. Every schema
draws its prefixes from one vocabulary, so the same concept has the same
atom in every flavor:

[cols="1,1",options="header"]
|===
| prefix | value
| `pub` / `co` | publisher / copublishers
| `series`, `subseries`, `sector` | series of the document
| `part`, `subpart`, `section`, `vol`, `issue` | sub-numbers, each its own atom
| `year`, `month`, `day` | publication date
| `ed`, `v`, `rev`, `upd`, `reaff` | edition, version, revision, update, reaffirmation
| `stage`, `iter` | stage and its iteration
| `sup`, `appendix`, `annex` | component families
| `lang` | languages
| `ids`, `sups`, `adopted` | nested identifiers
|===

== Open decisions for the owner

. *Facets in the slug.* The full URN must round-trip, so it keeps facets.
  If relaton wants one slug for each document (and not for each spelling),
  it cuts the `f` group, and the slug then does not round-trip. Decide which
  of the two the slug is.
. *Pubid-invented official URNs.* Only 14 flavors have an official namespace
  (below). The other flavors emit a `urn:<org>:…` form today that no
  organization registered. Keep it as legacy `#to_urn` with no round-trip
  promise, deprecate it, or make it round-trip as well.
. *The `pubid` NID.* `urn:pubid:` is not in the IANA registry. RFC 8141 asks
  for a formal or informal registration before public use.
. *Wire-format lock.* When the first slugs are published, the contract spec
  needs a stored snapshot of the URNs, so that a schema change that moves a
  published slug fails until a person approves it.

== Side-findings of the audit

Measured on `main` @ f404a7ca with the pinned engine (parsanol 1.3.122).

* `to_urn` raises for BIPM `Identifiers::Guide` (`Cannot build URN`), CSA
  (`undefined method 'publisher_prefix'`, 292 of 400 sampled ids), CCSDS
  translations (`undefined method 'code' for String`) and ETSI
  (`Integer("08")` on a month — the octal-literal hazard of `Integer()`).
* ISO `to_urn` drops the year (`ISO 4507:2007` → `urn:iso:std:iso:4507`):
  the RFC 5141 grammar carries no year, so the official form is lossy by
  design. This is the case that the pubid scheme exists for.
* IEC `to_urn` emits trailing empty segments (`…:2020:::`) for 74 of 400
  sampled ids.
* Under parsanol 1.3.127 (newer than the pin), every OIML parse raises
  `Parsanol::PARG::BindError` (`capture "doc_number" … bound nowhere`), and
  CIE parses 99 more ids than under 1.3.122. Re-check both before the next
  engine bump.
* `to_hash` serializes the internals of a component (stage registry data,
  typed-stage names) for some flavors, marked "Finding" below. Reduce those
  to the identifying value before their schema lands, or the URN carries
  registry data.
* adobe and sae have no pass fixtures, so their contract row has no corpus.

=== Proposed

Drafted from the `_type`s of each flavor and the `to_hash` keys observed over
its pass corpus (`ids` = how many identifiers of that type the corpus holds,
nested ones included). Tokens and prefixes are a proposal: they are fixed
when the flavor lands, against the vocabulary above. "core: number" means
that the type carries a `number`; an atom that always occurs can move into
the core when the flavor lands.
